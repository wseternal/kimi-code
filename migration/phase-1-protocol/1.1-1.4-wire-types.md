## Decisions

- Go generics used for Envelope[T] and PageResponse[T] — matches TS generic pattern cleanly.
- MessageContent uses a flat struct with optional fields instead of a sealed interface — simpler for JSON round-trip. Type field discriminates.
- events.ts is 1866 lines with 200+ event types — only the ~30 most critical event type constants are ported. The full event payload type catalog will be ported incrementally as each consumer needs them.
- SessionMetadata is `map[string]json.RawMessage` to handle the open/catchall Zod schema.
- WS control types faithfully preserve all 629 lines of the TS schema definitions (all 12 client operations + 4 server operations + terminal + event).

## Issues

- The TS `z.literal(true)` for ack payloads (e.g., `attached: z.literal(true)`) maps to Go `bool` since Go doesn't have literal types. The semantic is preserved by convention.
- events.ts imports from rest/config.ts creating a circular dependency — resolved by keeping event types in the protocol package and REST-specific config types in rest/.
