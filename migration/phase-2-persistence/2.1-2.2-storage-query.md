# Step 2.1–2.2 — Storage Engine + Query Layer

## Source

## Go Target

- `internal/persistence/store.go` — Store interface + FileStore (file-per-key) implementation
- `internal/persistence/query.go` — Query builder (prefix, cursor, limit, reverse) + AppendLog
- `internal/persistence/store_test.go` — 10 tests covering CRUD, nesting, scan, query, append log

## Decisions

- **No bbolt dependency yet** — network unavailable during implementation. FileStore provides the same interface; bbolt can be swapped in later as an alternative backend for better transactional semantics.
- **FileStore uses atomic writes** (write to `.tmp` then rename) to prevent partial writes.
- **Query builder** is a fluent API with cursor-based pagination matching the protocol's CursorQuery pattern.
- **AppendLog** provides journal-like semantics for the wire service's event log.

## Issues

- `go.etcd.io/bbolt` download timed out (network unavailable). FileStore serves as the initial backend; bbolt integration deferred to when network is restored.
- FileStore uses filesystem walking for Keys() which is O(n) — acceptable for MVP but bbolt will be faster for large datasets.
